# Spring 2025 与 Spring 2026 使用指南

这是版本隔离指南，不代替官方 handout。准确要求以对应目录中的 PDF、README 和 tests 为准。

## 共同主线

两届都沿用五阶段结构：Basics、Systems、Scaling、Data、Alignment。核心学习目标没有改变，但 2026 默认分支持续更新了依赖、接口、测试、集群/云端运行方式与部分作业要求。

## 已确认差异

- 官方仓库默认分支目前对应 Spring 2026；直接 `git clone` 得到的不是 2025 原版。
- 2026 作业普遍继续使用 `uv` 管理环境，并更新了 handout 与适配器。
- Assignment 2 的 2026 模板提供 staff `cs336_basics`，要求在 `cs336_systems` 中实现优化模型、分布式训练和优化器状态分片。
- Assignment 3 的 2026 版本提供 training API 客户端；校外学习者可安装 server extra 并本地运行，但 Stanford hosted API 身份认证不可假设可用。
- Assignment 4 的 2026 最终训练配置使用 Modal 与多张 B200；自学时必须设计缩小版数据/训练预算。
- Assignment 5 的 2025 历史版本保留在 `master` 血统中，2026 默认版本位于 `main`。

## 防止混用

1. 代码、笔记和实验标题都写明 `spring2025` 或 `spring2026`。
2. 不在两个版本之间直接复制 `tests/adapters.py`、`pyproject.toml` 或测试数据。
3. 复用个人实现时，通过小型兼容层适配，而不是修改官方测试掩盖差异。
4. 实验结果必须记录 commit SHA（见 [`UPSTREAM.md`](../UPSTREAM.md)）和硬件/依赖版本。
5. 先完成 2025 版本有助于利用成熟资料；随后以 2026 测试迁移实现并记录差异。

## 推荐双版本路线

- 主学习线：先做 Spring 2025，获得完整公开视频和社区资料支持。
- 迁移线：每完成一项 2025 作业，阅读 2026 handout，列接口差异，再移植实现。
- 对比产出：每项作业增加 `MIGRATION.md`，记录“要求变化、代码变化、实验变化、仍待验证”。

## 待持续核验

课程仓库可能在学期后继续修订。更新前先查看 commit 历史和 release notes；不要用“最新”覆盖固定快照而不记录差异。
